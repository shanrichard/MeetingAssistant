在项目根目录运行：

```sh
export CLANG_MODULE_CACHE_PATH="$PWD/.build/ModuleCache"
swift run --disable-sandbox --build-system native MeetingCoreChecks
swift run --disable-sandbox --build-system native AudioSafetyChecks
```

使用与 Swift 编译器兼容的 macOS SDK；如默认 SDK 不匹配，可通过 `SDKROOT` 指定已安装的兼容 SDK。`--disable-sandbox` 只关闭 SwiftPM 构建插件子沙盒，不更改系统安全设置。检查程序编译失败时不能视为检查通过。

## 其他回归入口

- `bash scripts/build-ui-regression.sh`：构建使用合成状态的原生界面回归程序。产物为 `.build/ui-regression/MeetingUIRegression.app`；以 `--check-summary` 启动可检查总结成功、失败、空输入及原文保留，以 `--check-deletion` 启动可检查删除流程，以 `--preview-blackhole` 启动可预览安装引导。总结回归使用假凭据和本地请求拦截。
- `bash scripts/check-credentials.sh`：用独立测试钥匙串条目和假 Key 检查保存、重启读取、替换、删除与跨版本读取。此检查会使用签名身份、创建并清理测试凭据；自签名版本的跨升级访问可能仍需要系统授权。
- `bash scripts/check-cloud-credentials.sh APPLE_DEVELOPMENT_IDENTITY TEAM_ID`：用调用者自己的 Apple 开发身份和团队完成云端签名的跨版本凭据检查。需要 Xcode 登录及相应权限，会连接 Apple 服务。

## 硬件检查

按需执行，先阅读各命令的作用：

| 命令 | 作用与边界 |
| --- | --- |
| `bash scripts/check-blackhole-setup.sh --devices` | 只读检查当前设备是否可用 |
| `bash scripts/check-blackhole-setup.sh --download` | 下载并校验官方 BlackHole 安装包，不执行安装 |
| `bash scripts/check-voice-output.sh --hardware` | 向 BlackHole 播放静音 PCM，检查重配置恢复；不改变系统默认输入 |
| `bash scripts/check-voice-output.sh --hardware-route` | 临时切换系统输入到 BlackHole 后恢复，核对系统输出未改变；仅在没有通话时运行 |

设备枚举、路由回读和本地播放完成计数只能证明相应的本地环节。真实会议软件的输入选择与远端听音需要独立验收。

## 真实会议验收步骤

1. 保存自己的 OpenAI API Key，选择物理麦克风及对外语言，戴上耳机。
2. 开始记录并完成音频权限授权；双方轮流说出数字、日期和短句，核对原文及译文。
3. 助手选择 BlackHole 2ch 作为译音输出；会议软件使用系统默认输入，或明确选择对应虚拟输入。固定设备选择不会跟随系统切换，需要分别验证。
4. 开启“发送我的译音”，由远端参会者确认收到译音；分别检查会议软件静音、停止发送、暂停及结束，确认路由恢复且没有过期译音继续播放。
5. 结束后核对实时原文、文字总结、引用跳转和 Markdown 导出。总结失败时应保留原文及旧总结；没有有效原文时不应上传录音补跑。
6. 在各会议软件分别重复，再进行设备切换、断网和长会议检查。记录应用版本、环境、步骤与结果，分享前移除录音、转写原文和凭据。
