# 签名与分发

[English README](../README.md#signing-and-distribution) · [中文 README](../README.zh-CN.md#签名与分发)

本地开发构建和正式分发使用不同的验证流程。请使用自己的 Apple 开发身份和团队；仓库不包含证书、私钥或钥匙串材料。

## 本地开发

未设置 `MEETING_SIGNING_IDENTITY` 时，`bash scripts/build-app.sh` 会创建项目专用的自签名开发身份，材料保存在 `~/Library/Application Support/MeetingAssistant/DevelopmentSigning/`。脚本不修改证书信任或默认钥匙串，但会将专用钥匙串加入用户搜索列表。

二进制更新后，系统可能要求重新授权钥匙串访问，或在设置中重新保存 API Key。开发签名不等于 Apple 公证，也不应被当作他人安装体验的验证。

## 本地 Developer ID

使用自己的 Developer ID Application 身份：

```sh
export MEETING_SIGNING_IDENTITY='Developer ID Application: YOUR NAME (YOUR_TEAM_ID)'
bash scripts/check-credentials.sh
bash scripts/build-app.sh
swift scripts/create-archive.swift dist/MeetingAssistant.app dist/MeetingAssistant.xcarchive
```

构建启用 Hardened Runtime、安全时间戳和 `Resources/MeetingAssistant.entitlements` 中的麦克风权限。归档脚本检查证书类型、权限及调试标记。

`check-credentials.sh` 使用独立测试条目和假 Key，测试保存、重启读取、替换、删除及升级访问，不使用产品的用户凭据。

## Xcode 云端签名

没有本地 Developer ID 私钥时，可先用自己的 Apple Development 身份构建应用，再准备云端签名归档：

```sh
swift scripts/create-archive.swift --for-cloud-signing PATH_TO_DEVELOPMENT_APP.app dist/MeetingAssistant-for-signing.xcarchive
```

在 Xcode Organizer 选择 Direct Distribution，使用具备云端 Developer ID 权限的账号完成签名与公证。云端签名前的归档不是最终分发包。

跨版本凭据检查入口：

```sh
bash scripts/check-cloud-credentials.sh APPLE_DEVELOPMENT_IDENTITY TEAM_ID
```

此命令会连接 Apple 服务，导出两个独立测试版本，在同一路径检查假 Key 的保存、重启、升级、回退与删除，并清理测试条目和文件。

## 分发前验证

1. 导出公证后的应用，检查 Developer ID、Hardened Runtime、麦克风权限、安全时间戳和公证票据。
2. 验证严格代码签名和 Gatekeeper，再压缩最终应用。
3. 在另一台 Mac 验证首次安装、权限申请、API Key 保存及重启读取。
4. 验证跨升级凭据访问、虚拟设备安装与真实会议对端听音；范围见 [验证与验收](验证记录.md)。

签名私钥、证书导出、钥匙串数据库与密码文件不得加入 Git；分发包也不应携带这些材料。
